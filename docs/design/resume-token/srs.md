| REQ-040 | FR | must | `decodeResumeToken(text)` trong `src/tools/resumetoken.js` nhận chuỗi hex (hoa hoặc thường, có thể có khoảng trắng đầu/cuối, có thể nằm trong một cặp nháy `"…"` hoặc `'…'`), JSON `{"_data": "…"}`, JSON có `_id._data`, hoặc dạng mongosh `{ _data: '…' }` / `{ _id: { _data: '…' }, … }` (khóa không nháy, nháy đơn; không phải JSON hợp lệ), và trả về `{ timestamp: {t, i}, version, tokenType, txnOpIndex, fromInvalidate, uuid, documentKey \| eventIdentifier }` theo `design.md` D1-D2. Với token mẫu của README gói npm (`82612E8513000000012B022C0100296E5A1004A5093ABB38FE4B9EA67F01BB1A96D812463C5F6964003C5F5F5F78000004`) kết quả là t=1630438675, i=1, version 1, tokenType 128, txnOpIndex 0, fromInvalidate false, uuid `a5093abb-38fe-4b9e-a67f-01bb1a96d812`, documentKey `{ _id: '___x' }`. Các trường `tokenType`, `fromInvalidate` chỉ có khi version ≥ 1; `uuid` và `documentKey`/`eventIdentifier` chỉ có khi token chứa chúng. Version 2 trả `eventIdentifier` (token thật của MongoDB 7 là version 2, `eventIdentifier = {operationType, documentKey}`), version 0/1 và mọi version khác trả `documentKey`. Giá trị mức trên cùng phải được theo sau bởi ít nhất một byte nữa (thường là byte kết thúc `0x04`); token kết thúc ngay sau giá trị cuối là lỗi "cut off" (nên mọi tiền tố của token README đều lỗi). Các byte dư sau documentKey/eventIdentifier bị bỏ qua. Tên trường của object giữ đúng thứ tự trong token, kể cả tên số nguyên (`{b:1, '10':2}` không bị đảo) và tên trùng. *Sửa sau khi build: thêm dạng nháy/mongosh, thứ tự trường, quy tắc byte cuối (reviewer vòng 1; `test/tools/resumetoken.test.mjs`: "the shell form and quoted hex", "object fields keep the token order", "a token cut at any position throws").* | Đây là toàn bộ nhu cầu của người dùng. | Test |

| REQ-042 | FR | must | Đầu vào sai (hex lẻ, ký tự không phải hex, token bị cắt, kiểu không biết, JSON không có `_data`) ném lỗi tiếng Anh rõ ràng, không bao giờ `RangeError`/`TypeError` của JavaScript; thông báo chép đầu vào tối đa 120 ký tự. Đầu vào 1 MB hex hoặc lồng 100.000 tầng xong dưới 1.000 ms (lỗi hoặc kết quả), không tràn ngăn xếp. Giới hạn trong `src/tools/resumetoken.js`: hex tối đa 1.048.576 chữ số (`MAX_HEX`), văn bản dán tối đa 4.194.304 ký tự (`MAX_TEXT`), lồng tối đa 200 tầng (`MAX_DEPTH`), tối đa 20.000 giá trị trong một token (`MAX_VALUES`) và tổng "trọng số" 400.000 (`MAX_WEIGHT`, mỗi giá trị tính một lần cho mỗi tầng nó nằm trong, nên 20.000 giá trị trong 190 mảng lồng nhau vẫn bị từ chối). | REQ-043 | FR | must | Tool `resumetoken` (tiêu đề "Resume token") nằm trong panel cạnh `objectid`, hiện các trường của REQ-040 thành từng dòng có nút sao chép (giống tool ObjectId): Timestamp `{t, i}`, giờ UTC (ISO) và giờ địa phương, Version, Token type (128 = event, 0 = high water mark, số khác hiện số), Txn op index, From invalidate, Collection UUID, documentKey/eventIdentifier dạng Extended JSON (relaxed, có thụt lề). Tên các dòng trong `src/views/resumetoken.js`: `Timestamp` (dạng `{ t: …, i: … }`), `Time (UTC)`, `Local time`, `Version`, `Token type` (kèm nhãn `event` hoặc `high water mark`; số khác chỉ hiện số), `Txn op index`, `From invalidate`, `Collection UUID`; hai dòng cuối chỉ hiện khi token có trường đó; khối `documentKey` hoặc `eventIdentifier` (có nút Copy) in bằng `toExtendedJson` (thụt lề 2).
